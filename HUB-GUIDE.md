# СДВГ hub: полный кит "19 сайтов за 4 минуты"

Это всё, что я не стал выкладывать в публичку. Если в публичном гайде было "что делать", то тут "как именно": готовые файлы, автосбор базы, промпты в том виде, в котором они реально отработали, и продажи с разбором моих ошибок.

Эта версия адаптирована под Kimi Code: сами роли, запреты и пайплайн не менялись, поменялась только механика запуска (модели, папка агентов, браузер для фото).

## Что в архиве
```
kit/
  AGENTS.md                  правила проекта (короткие, читаются каждый ход)
  PLAN.md                    память проекта по шагам
  PROMPTS.md                 все промпты по шагам + модель и effort на каждый
  HUB-GUIDE.md               этот файл
  agents/
    biz-researcher.md        3 штуки параллельно, вторичная модель (K2.7 Code Highspeed)
    photo-collector.md       1 штука, браузер Playwright, основная модель (K3)
    page-writer.md           3 штуки параллельно, основная модель (K3)
    qa-checker.md            проверка, вторичная модель (K2.7 Code Highspeed)
  tools/
    no_site_leads.py         выгрузка парсера → готовый "local businesses.md" (только без сайта)
  sales/
    CALL-SCRIPT.md           звонок, развилки, тайминг
    FOLLOW-UP.md             дожим после ссылки по дням
    PRICING.md               пакеты, как называть цену, допродажи
    pipeline-template.csv    таблица продаж
```
Копируешь AGENTS.md, PLAN.md и PROMPTS.md в корень своего проекта, файлы из agents/ - в ~/.kimi-code/agents/ (плоско, без вложенных папок), правишь город, ниши и имя в плашке. Открываешь проект в Kimi Code. Дальше идёшь по PROMPTS.md.

## 1. Пайплайн целиком

```
Сбор базы (парсер или руками)
  → local businesses.md
  → 3 x biz-researcher (данные, прайс, отзывы)      ~3 мин
  → photo-collector (фото от владельца)              ~10 мин
  → эталон + контрольная страница (K3.1 Pro)         ~15-30 мин с правками
  → 3 x page-writer (рой)                            ~4 мин
  → qa-checker (вычищает выдумки)                    ~5 мин
  → деплой демок на GitHub Pages                     ~5 мин
  → pipeline.csv: угол захода + комплимент на каждого
  → звонки
```
У меня от первого промпта до живых ссылок ушло около 2,5 часов, из них большая часть - правки эталона и ручной сбор базы. С парсером сбор базы сжимается до 10 минут.

Лимиты: у меня на Claude это было 42% одного пятичасового окна Pro на всё (окно Pro - это квота подписки Anthropic, в Kimi Code её нет: там оплата за токены, но арифметика та же). Главная экономия - модели по ролям, чистый контекст между шагами и отчёты агентов в 3 строки.

## 2. Автосбор базы: parser-2gis-new

То, ради чего стоит этот кит. Ручной отбор в 2ГИС - нормально для 20 бизнесов, но для масштаба в сотню и больше (а именно он нужен, см. раздел 6) руками ты сдохнешь.

**Репо:** https://github.com/Eroloft/parser-2gis-new
Это свежий форк известного parser-2gis (оригинал 400+ звёзд, давно не обновлялся). В форке починили парсинг в headless-режиме, добавили веб-интерфейс, генератор ссылок город + рубрика и, главное, фильтры лидов: без франшиз, только с телефоном, по минимальному рейтингу и числу отзывов. Лицензия LGPLv3.

Почему он лучше того, что было в видео:
- **Часы работы.** Через FetchURL агент их не видел, приходилось писать руками. Парсер отдаёт колонку "Часы работы".
- **Сотни бизнесов за раз** по нескольким рубрикам и городам.
- **Готовые фильтры** без франшиз, с телефоном, рейтинг 4.5+, от 20 отзывов.

Чего в нём нет: фильтра "БЕЗ сайта" (есть только "с сайтом"). Для этого в кит положен `tools/no_site_leads.py`: берёт CSV парсера, выкидывает всех, у кого есть настоящий сайт (ВК, Taplink, 2ГИС, YCLIENTS и подобное сайтом не считаются), сортирует по рейтингу и отзывам и пишет готовый `local businesses.md` в нужном формате, вместе с часами и телефоном.

Установка (Python 3.8+, нужен Google Chrome):
```
git clone https://github.com/Eroloft/parser-2gis-new
cd parser-2gis-new
python -m venv .venv
.venv\Scripts\activate
pip install -e .
parser-2gis-new
```
Последняя команда открывает веб-интерфейс: выбираешь город, рубрику, ставишь фильтры, жмёшь старт, получаешь CSV.

CLI-вариант (удобно давать агенту):
```
parser-2gis-new -i "{ссылка 2ГИС на рубрику в городе}" -o data/raw/avtoservis.csv -f csv --filters.dedup-franchises yes --filters.require-phone yes --filters.min-rating 4.5 --filters.min-reviews 20
python tools/no_site_leads.py data/raw/avtoservis.csv --niche "автосервис" --limit 40 -o "local businesses.md"
```

**Важно, без этого никак:**
- Парсинг сайтов - серая зона по правилам самого 2ГИС. Используй для своего поиска клиентов, без бешеных объёмов и без перепродажи базы. Не ставь минимальные задержки, не долби сервис сутками.
- Телефон ИП - это часто личный номер человека, то есть персональные данные. Звонить конкретному бизнесу с конкретным предложением - нормально. Массовые рассылки и продажа базы - нет.
- Чистый официальный путь - Places API 2ГИС (docs.2gis.com). Там есть демо-ключ для тестов: регистрируешься в кабинете разработчика и создаёшь его. Часть полей платная, лимиты на демо небольшие, но для проверки своей ниши на 30-50 бизнесов хватает.

## 3. Агенты: почему они такие

**biz-researcher (вторичная модель K2.7 Highspeed, 3 параллельно).** Сбор данных - механика, тут не нужна умная модель. Узкие инструменты: FetchURL, Read, Write. Если 2ГИС отдал ошибку, агент записывает только то, что знает, и не придумывает. У меня один сервис отдал 410, и агент сделал ровно это.

**photo-collector (основная модель K3, 1 штука).** Работает в браузере Playwright, поэтому один: браузер один, и два агента в нём подерутся. Обычные запросы 2ГИС заворачивает на антибот, а браузер пускает. Агент находит ссылки на фото "от владельца", меняет размер в URL на 1280x720 и качает напрямую с CDN, это работает уже без браузера.

Нюанс, на котором я спалился: если фото от владельца нет, агент берёт "превью организации". Иногда это рекламный баннер самого 2ГИС (премия 2ГИС с наклейкой). Владелец увидит на своём сайте чужую рекламу. В версии агента из кита это уже запрещено.

**page-writer (основная модель K3, 3 параллельно).** Пишет ТОЛЬКО content/{slug}.json. Шаблон, темы и сборку не трогает: три агента, правящие один шаблон, = гарантированная каша.

**qa-checker (вторичная модель K2.7 Highspeed).** Самый недооценённый агент. В моём прогоне копирайтеры навыдумывали цены (химчистка, которой у сервиса нет, 8 цен из воздуха у другого). В версии из кита проверяльщик сверяет каждую цену и каждую услугу с research-данными, а не только телефон и адрес.

## 4. Эталон: что реально решает

- Эталон делай на самой сильной модели (K3.1 Pro, effort high), весь остальной пайплайн - на основной (K3). Дизайн - единственное место, где модель видна глазами.
- Обязательно контрольная страница без фото. Если шаблон некрасив без фото, треть твоих сайтов будет некрасивой.
- Правки шаблона после роя делай ОДНОЙ правкой шаблона, а не агентами по страницам. Мой баг "на телефоне всё уезжает на 9 px из-за карты" был общим на все 19 страниц и починился одной строкой CSS.
- Главный экран для автосервиса: кнопка звонка и телефон крупно. Красота второстепенна, звонок первичен.

## 5. Продажи: мои цифры и мои ошибки

19 звонков → 11 согласились посмотреть → контакты почти все в MAX → 4 удалили чат через день, 1 не прочитал, остальные молчат → 1 заинтересован → договорились на 15 000.

Где я потерял людей и как это исправлено в sales/:
1. **Ссылку отправлял после звонка.** Через час человек уже не помнит, кто ты, и незнакомая ссылка = спам. Исправление: отправляешь, пока он на линии, и ждёшь "пришло".
2. **Голая ссылка без контекста.** Исправление: "это {имя}, только что созванивались" + скрин первого экрана + ссылка.
3. **Не договаривался о следующем шаге.** Исправление: "когда удобно перезвонить и услышать ваше мнение?"
4. **Не перезванивал прочитавшим.** Молчание после прочтения чаще значит "руки не дошли". Звонок на следующий день возвращает часть из них.

Подробно по дням - FOLLOW-UP.md. Скрипт и развилки (администратор, "некогда", "не интересно") - CALL-SCRIPT.md. Пакеты и как назвать цену - PRICING.md.

## 6. Как из эксперимента сделать заработок

Математика из моего прогона: 1 заинтересованный на 19 звонков. Если исправить ошибки из раздела 5, реалистично выходит 1 на 10-12. Значит:
- 100 бизнесов в неделю → примерно 8-10 заинтересованных → 3-5 сделок по 15 000.
- База на 100 бизнесов: парсер + no_site_leads.py, 15 минут.
- Сайты на 100 бизнесов: те же агенты, рой в 3-4 захода по 25-30 штук (лимиты).
- Звонки: 100 звонков в одиночку - это 2 полных дня. Возьми 1-2 друзей на обзвон, плати за результат: фикс за взятую ссылку + процент со сделки (например, 300 ₽ за ссылку и 20% со сделки). Дай им CALL-SCRIPT.md и pipeline.csv.

И сразу думай про допродажи: поддержка 1 000-2 000 в месяц, карточки на картах, соцсети. Один сайт - это 15 000 один раз, десять клиентов на поддержке - это ежемесячный плюс, который не надо искать заново.
